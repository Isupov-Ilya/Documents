# Windows-продукт: сборка и проверка

Сборка: CPython 3.11 x64, PySide6 6.8, faster-whisper/CTranslate2 CPU, Sherpa ONNX, llama-cpp-python, python-docx. Установщик Inno Setup устанавливает программу в пользовательскую папку без административных прав. Модели и интервью сохраняются отдельно от программы; удаление приложения не должно удалять папку данных.

FFmpeg — LGPL shared build. Подготовительный скрипт требует опубликованный SHA-256, сохраняет источник и копирует сопутствующие библиотеки и лицензии. Не используются параметры отключения TLS или проверки сумм. Модели загружаются по зафиксированным ревизиям и суммам из ресурсов приложения. WeSpeaker изменяется только в отдельном производном файле для добавления метаданных Sherpa; исходные веса сохраняются.

Контрольный прогон GitHub Actions:

1. Собрать приложение нативно на Windows и создать установщик.
2. Установить его в путь с кириллицей.
3. Удалить Python и инструменты разработки из PATH дочернего приложения.
4. Подготовить модели штатной командой EXE.
5. Преобразовать синтетическое интервью в M4A и запомнить SHA-256.
6. Убедиться, что контрольное соединение EXE доступно до блокировки.
7. Создать исходящие Windows Firewall Block-правила для приложения и его EXE-инструментов; проверить отказ контрольного соединения.
8. Обработать M4A с настоящими ASR, диаризацией и LLM. При необходимости отдельно зафиксировать разрешённое ТЗ ручное уточнение ролей из синтетической разметки.
9. Проверить реальные факты/источники, отдельные лица, конфликтующие даты, три DOCX, отсутствие персональных сведений образца и сохранение таблицы.
10. Открыть штатное окно через Windows-плагин Qt, загрузить транскрипцию и локальное аудио, сохранить снимок окна.
11. Сверить неизменность исходного аудио и снять тестовые Firewall-правила.
12. Публиковать установщик и доказательства только при успехе проверок.

Модели не имитируются. Режим demo с заранее размеченными ответами не используется как доказательство работы моделей. Папка validation включает JSON-отчёт, журнал обработки, контроль Firewall, снимок окна и версии установленных пакетов.

Чего проверка не доказывает: статистическое качество на реальных интервью, работу GPU, полную смысловую корректность автоматического извлечения или поддержку каждого элемента произвольного DOCX. Часовая приёмка на независимом корпусе остаётся отдельной задачей; короткий тест не выдаётся за неё.

## Измерения для версии 0.2.3

Установленный EXE на Windows Server 2022 обработал синтетическое M4A длительностью 52,55 секунды при блокировке исходящей сети для программы и её инструментов. Получены три DOCX, загружены транскрипция и локальное аудио в штатном окне. Обработка заняла 813 секунд, выборочный пик памяти дерева процессов составил около 5,7 ГБ. См. [отчёт и снимки окна](https://github.com/Isupov-Ilya/Documents/releases/download/v0.2.3-windows-13/Windows-validation.zip).

В отдельном испытании того же установщика синтетический диалог был повторён до 3 600 секунд. Под блокировкой сети диаризация и распознавание создали транскрипцию из 1 222 фрагментов. После подтверждения ролей зафиксированы ответы модели по 508 уникальным фрагментам. GitHub Actions остановил задание по шестичасовому лимиту во время извлечения сведений, до создания DOCX. Полный цикл для часовой записи не подтверждён. Это измерение относится к CPU тестового сервера и синтетическому примеру. См. [часовой прогон и его промежуточные файлы](https://github.com/Isupov-Ilya/Documents/actions/runs/45116165580).

Проверка источников отклоняет выдуманные цитаты. Допустимо восстановление цитаты через непосредственно соседние фрагменты одной реплики, когда каждый добавленный символ буквально есть в исходной транскрипции; добавленные ссылки сохраняются и требуют проверки. Неподтверждённые новые упоминания уже известного человека не заменяют прежние подтверждённые ссылки. Несопоставимые утверждения не считаются установленным противоречием. Разные явно процитированные годы рождения сохраняются отдельными утверждениями.

Автоматические предложения модели с отсутствующей цитатой, неподтверждённым лицом или неоднозначным повторяющимся ID помещаются в карантин до объединения с проверенными данными. Сведение с несколькими цитатами отклоняется целиком, если хотя бы одна не подтверждается. Исходный ответ сохраняется в `facts_batch_*.json`, причины — в `facts_rejections_*.json`; замечания попадают в документ, а неотражённый материал остаётся доступным для проверки по транскрипции. Выполняется один дополнительный проход по неотражённым ответам респондента. Это предотвращает аварийное завершение всего задания из-за одного выдуманного источника и не означает подтверждения остальных утверждений по смыслу. Загрузка и экспорт сохранённых/отредактированных данных по-прежнему проходят строгую проверку источников; карантин применяется только к новым автоматическим предложениям.
